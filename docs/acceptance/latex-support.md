# LaTeX compilation acceptance — local tools, eager builds and SyncTeX

Run this manually against a built Puddle cockpit on every supported host family
before release. Unit tests use fake tools and fixture output; this script covers
the behaviours that need a real TeX installation, filesystem watcher, PDF.js
canvas and Monaco instance.

Start the daemon from a plain shell, never from inside a coding-agent session
(see `CLAUDE.md`). Use a disposable Puddle home so managed output is easy to
inspect:

```sh
pnpm build
export PUDDLE_HOME=$(mktemp -d)
node packages/daemon/dist/index.js
```

Connect the CLI/cockpit to that daemon through the normal development launch
path. Create a project containing this fixture:

```text
latex-acceptance/
├── main.tex
├── references.bib
└── sections/
    └── result.tex
```

`main.tex`:

```tex
\documentclass{article}
\usepackage{hyperref}
\begin{document}
\input{sections/result}
\bibliographystyle{plain}
\bibliography{references}
\end{document}
```

`sections/result.tex`:

```tex
% !TEX root = ../main.tex
An accepted result cites \cite{puddle}.
```

`references.bib`:

```bibtex
@misc{puddle, title={Puddle acceptance}, year={2026}}
```

## 1. Capability discovery and controls

1. Open `main.tex` and `sections/result.tex`. Each TeX tab has a play triangle
   and lightning control; it has no Markdown/HTML source/preview/linked/locked
   toggle.
2. Hover each control. The play tooltip says it compiles on demand. The
   lightning tooltip says it enables eager compilation; its accent state
   reflects the persisted mode.
3. Confirm the capability comes from the daemon host. For an SSH cockpit, a TeX
   installation on the browser machine alone must not enable the controls, and
   an installation only on the remote daemon host must enable them.
4. Verify discovery on the host's ordinary `PATH`. Also test one sparse service
   environment where MacTeX/TeX Live/TinyTeX/MiKTeX is installed in a supported
   conventional location but absent from that reduced `PATH`.
5. On a no-tool host, TeX remains an ordinary editable source file without
   compile controls. Puddle does not attempt to install a distribution.

Record the selected executor from `GET /api/compilation/capabilities`. Exercise
the setups available to the release host matrix:

- `latexmk` is preferred when installed;
- Tectonic is selected when `latexmk` and an explicit `% !TEX program` are
  absent; and
- otherwise a local `pdflatex`, `xelatex` or `lualatex` engine runs bounded
  passes, with `biber`/`bibtex` when the document requests one.

## 2. On-demand build and managed output

1. Add an unsaved visible edit to `sections/result.tex`, then press play on that
   tab. The source tab activates first, the edit saves, and the build resolves
   `% !TEX root` to `main.tex`.
2. A successful build opens `main.pdf` as an ordinary persistent file tab in
   the same pane. Its label is not italicised. It can be moved, split, restored
   and closed like any other file tab.
3. Press play again. The existing rooted PDF tab is selected and refreshed;
   no duplicate opens. Put that PDF in another pane and repeat: Puddle finds it
   across the whole live layout rather than opening another copy.
4. Inspect the fixture directory with `git status --short` and `find`. It has no
   `.aux`, `.bbl`, `.bcf`, `.blg`, `.fls`, `.log`, `.out`, `.synctex.gz` or PDF
   generated by the build.
5. Inspect `$PUDDLE_HOME/latex/<document-hash>/`. Intermediate files are below a
   fresh `runs/<id>/`; the stable PDF, SyncTeX index, build log and manifest are
   below `current/`. At most five run directories remain.

Repeat with source/root paths containing spaces and non-ASCII characters.

## 3. Failures, diagnostics and last-good output

1. With `main.pdf` open, introduce `\definitelyUndefinedCommand` on a known
   line in `sections/result.tex` and press play.
2. The failure is visible as an error notification. Expanding **Show compiler
   output** reveals the bounded TeX output with its original line breaks; the
   process failure is not reduced to a silent spinner or generic exit code.
3. Open `sections/result.tex` in Monaco. The failing line has an error marker
   and hover message sourced from the compiler diagnostic, including when the
   error belongs to an included file rather than `main.tex`.
4. The previous successful PDF remains readable and is not replaced by a
   partial/failed result.
5. Correct the line and compile successfully. The compiler marker clears and
   the already-open PDF refreshes.
6. Repeat with a classic TeX `! …` / `l.<number>` error if the local package
   emits one; it should resolve to a source line or remain fully readable in the
   expandable output when it cannot be normalised.

## 4. Eager mode and external writes

1. Enable the lightning control on `main.tex`. It performs one initial build.
2. Edit and save `sections/result.tex`. After the debounce settles, exactly one
   build runs and the PDF refreshes without changing the active pane, tab,
   Monaco caret or focus.
3. Change the file from a plain terminal, then by atomic replacement (write a
   temporary file and rename it over the dependency). Both trigger eager builds.
4. Save several rapid changes while a build is running. There is one active run
   and at most one follow-up run for the dirty state; stale output never replaces
   the newest successful PDF.
5. Introduce an error during eager mode. The expandable failure notification
   and Monaco marker appear; fixing the watched input triggers a later successful
   build without toggling eager mode off and on.
6. If the PDF is absent, eager success adds one persistent PDF tab beside the
   source in the background without stealing focus. If it is already open, only
   that tab refreshes.
7. Disable eager mode, then change a dependency: no build occurs. Re-enable it,
   reload/reconnect the cockpit and confirm the persisted source tab registers
   again. Closing the last eager copy retires the watcher.

## 5. PDF rendering and inverse SyncTeX

1. A generated LaTeX PDF uses the owned PDF.js viewer. An unrelated PDF opened
   from the worktree still uses the browser's native viewer and does not load
   LaTeX navigation behaviour. In a packaged CLI/desktop cockpit, confirm the
   emitted `pdf.worker*.mjs` request succeeds with a JavaScript content type;
   module workers must never be served as `application/octet-stream`.
2. Resize the pane and use a multi-page document. Pages remain fitted and crisp
   on a HiDPI display; later pages paint as they approach the viewport.
3. Command-click on macOS or Ctrl-click elsewhere on visible text in the PDF.
   Puddle opens or reuses the corresponding source tab and places Monaco's caret
   at the returned line. Click text emitted by `sections/result.tex`: navigation
   lands in that included file, not forcibly in `main.tex`.
4. Repeat at different pane widths and on later pages. Ordinary clicks retain
   normal PDF behaviour.
5. Remove the SyncTeX index or test a host without the `synctex` query command.
   The viewer reports an actionable error and leaves the current source
   selection intact.

## 6. Host and safety matrix

Run the relevant sections on macOS with MacTeX/TeX Live, Linux with TeX Live or
TinyTeX, WSL with its Linux-visible distribution, a Tectonic-only host, a
raw-engine-only host, a no-tool host, and at least one real SSH host. Confirm in
every case that:

- commands run on the daemon host without a shell or shell escape;
- `% !TEX root` cannot escape the selected worktree/external root and
  `% !TEX program` cannot name an arbitrary executable;
- a compiler timeout or daemon shutdown terminates the process group;
- generated and intermediate output stays entirely under `PUDDLE_HOME/latex`;
- inverse SyncTeX rejects a forged/non-managed PDF root and any result outside
  the original source root; and
- reconnecting the browser re-registers eager modes represented by persisted
  live source tabs.

Record host/tool versions and any mismatch as an issue. Provider-specific fixes
belong under `packages/daemon/src/latex/`; generic scheduling, mode and watcher
fixes belong under `packages/daemon/src/compilation/`.
